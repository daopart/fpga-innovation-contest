# 基于 EG4S20 的 HDMI 多媒体播放器

安路 EG4S20BG256

## 1. 项目概况

这是一个不跑软件的 HDMI 播放器。板子上没有 CPU，也没有操作系统：上电以后，FPGA 直接从 TF 卡里读 BMP 图片和 WAV 音乐，经过缩放、转场、字幕、画质调节等几级处理后送到 HDMI 接口，声音以 I2S 形式嵌在 HDMI 数据流里。整个操作只用板上的 4 个按键和 4 个拨码开关。

做这个题目的出发点是想看看，不用处理器和软件栈，只用 Verilog 和 FPGA 内部的逻辑资源，能把一个多媒体播放器做到什么程度。实际做下来，图片切换、音频播放和字幕叠加都能稳定运行，整机资源占用也在 EG4S20 的范围内。

## 2. 功能

图片部分：上电后从 TF 卡里找 640×480、24 位、未压缩的 BMP，最多认 4 张，放在 SDRAM 的两个帧缓冲里轮流显示。可以手动换图，也可以打开自动轮播。缩放有 0.5×、1×、2×、4×、8× 五档，翻转有正常、左右镜像、上下镜像、180° 四档。

转场有 4 种：直切、压黑淡入淡出、从左往右、从上往下。字幕是底部半透明黑条加 24×24 的行楷艺术字，共 4 页；字幕打开时，换图会自动翻页。亮度、对比度可以调，按键时左上角会显示当前数值；另外还有关闭、反色、灰度三档滤镜。

音频方面，TF 卡根目录下的 WAV 会被流式读出，通过 I2S 送进 HDMI，支持 48 kHz、16 位、单声道的 PCM。播放时右上角有一个 16 段的频谱柱状图，数据来自 I2S 回环采样。

还没出图的时候，屏幕显示赛事视觉和一条进度条，进度条约 6.7 秒走满。上电画面的效果见 `doc/boot_preview.png`。

## 3. 整体结构

视频通路大致是这样：

```
TF 卡 ──SPI──> sd_card_bmp ──> SDRAM 双帧缓存
                                   │
                             frame_read_write
                                   │ 按行读
                                   ▼
video_timing_data ──> video_zoom ──> video_transition ──> video_bright_contrast
   (640×480 时序)      (缩放/翻转)      (4 种转场)          (亮度/对比度/滤镜)
                                                               │
                                                               ▼
HDMI 1.4b 发射 <── rgb_to_axis <── audio_wave <── adj_osd <── subtitle_overlay
   (视频+音频)       (RGB→AXIS)     (16 段频谱)   (参数 OSD)   (24×24 字幕)
```

几个模块的延迟不一样：缩放要读行缓存，转场要等场起始，亮度对比度是 2 拍，字幕是 3 拍，OSD 是纯组合。所以每一级都把 `de` 和 `vs` 跟着像素一起往后传，后面的模块用上一级给的同步信号，而不是拿最早的时序。这样改链路时不容易出现画面整体偏移。

音频通路是另一条：

```
TF 卡 WAV ──FAT──> wav_reader ──> 1024×24 异步 FIFO ──> I2S 64fs ──> HDMI
                                                          │
                                                          └── I2S_receiver ──> 频谱 / ACR
```

WAV 读取和图片读取共用一个 SD 读口，按扇区仲裁：音频缓冲快空的时候优先补音频，其余时间让给换图。48 kHz、16 位的单声道数据率大约 96 KB/s，SD 卡读带宽足够，FIFO 也能盖住换图时的抖动。

时钟一共有三组。输入是 50 MHz 晶振，`sys_pll` 产生 100 MHz 的 SD 卡时钟和 125 MHz 的 SDRAM 时钟，`video_pll` 产生 25 MHz 像素时钟和 125 MHz 的 TMDS 串行时钟，音频 PLL 产生 12.288 MHz 的主时钟。跨时钟域的信号都经过异步 FIFO 或两级、三级同步器，慢变量（转场档位、字幕页、缩放档）打两拍后再用。

## 4. 操作

板上丝印和代码里的端口名不是一一对应的，下面按丝印写。

| 丝印 | 引脚 | 类型 | 操作 |
|---|---|---|---|
| KEY1 | A2 | 按钮 | 整机复位，重新初始化 SD 卡并重新扫卡 |
| KEY2 | B2 | 按钮 | 单击下一张；双击切换转场；长按放大一档 |
| KEY3 | B1 | 按钮 | 单击亮度 −；双击切换滤镜；三连击切下一首歌 |
| KEY4 | C1 | 按钮 | 单击自动轮播开关；双击切换字幕页；长按缩小一档 |
| SW1 | C8 | 拨码 | 亮度 + |
| SW2 | C7 | 拨码 | 对比度 − |
| SW3 | C6 | 拨码 | 对比度 + |
| SW4 | C5 | 拨码 | 图片翻转，正常 → 左右 → 上下 → 180° 循环 |

按键消抖 10~16 ms，双击窗口 320 ms，长按门限 800 ms。三连击要三下都落在 320 ms 窗口里，松手后约 0.3 秒才切歌，所以不会顺带触发双击的滤镜。拨码开关是自锁的，只做“一步动作”，不参与双击和长按。

8 位数码管默认是诊断模式，从左到右依次是：

| 位 | 显示内容 |
|---|---|
| 1 | SD 卡初始化完成 |
| 2 | 卡上找到的 WAV 数量；格式不对时显示 E |
| 3 | 当前按下的键号（1–7，松开后保持约 2 秒） |
| 4 | 扫到的图片数量（0–4） |
| 5 | 是否已经有有效图像 |
| 6 | 是否还卡在复位（PLL 没锁） |
| 7 | 当前曲目（0 表示不放卡上的歌） |
| 8 | SD 状态码（0 初始化 / 1 空闲 / 2 扫描 / 3 等待 / 4 读图） |

把 `top_tf_hdmi_audio.v` 里的 `DIAG_MODE` 改成 `1'b0`，会换成翻转档、滤镜档、图片数、字幕页、转场档等常规信息，但缩放档在当前版本里不显示。

上电后大约 0.2 秒 HDMI 锁定，出现开机动画；1 秒左右 SD 卡初始化完成，开始找 WAV；扫到 BMP 后画面切回图片。如果数码管第 1 位一直是 0，先检查 TF 卡和卡座；第 5 位一直是 0，说明没有扫到符合要求的 BMP。

板上的 SW6 是数码管和双色 LED 的选择开关，要拨到数码管一侧，否则整排数码管不亮。HDMI 要接板上的 HDMI-B 口，声音只从 HDMI 出来，板上没有喇叭。

## 5. TF 卡里放什么

卡用 FAT16 或 FAT32 都行，文件放在根目录。BMP 和 WAV 都不看文件名，只看文件头。

BMP 要求 640×480、24 位、无压缩，最多认 4 张。上电后从第 0 扇区开始顺序扫描前 64 MB，按 `BM` 文件头、宽高、位深和压缩方式判断，所以图片要连续存放，别放在卡的后半段。文件名随意，`IMG01.BMP` 这类命名只是方便自己看。

WAV 要求 48 kHz、16 位、单声道、PCM，标准 44 字节文件头，最多认 8 首。程序优先读 FAT 根目录里的目录项，拿到起始簇和长度后直接从数据区流式播放；卡上没有可识别的 FAT 结构时，会退回逐扇区扫描。44.1 kHz、24 位、双声道、MP3 都不支持。

`demo/` 目录里放了 4 张示例图片和 1 首示例音乐，把里面的文件全部拷到 TF 卡根目录就能直接演示。音乐可以用 ffmpeg 从其他格式转：

```
ffmpeg -i 歌.mp3 -ar 48000 -ac 1 -c:a pcm_s16le MUSIC.WAV
```

如果卡上没有 WAV，或者当前曲目选到 0，输出是静音。工程里保留了内置旋律的代码和 `melody_rom.v`，但 `MELODY_ENABLE` 默认是 0，不会自动回退到旋律。

## 6. 编译与上板

工程用安路 TD 6.2.1（6.2.168116）建立，顶层模块是 `top`，器件 EG4S20BG256。

1. 打开 TD，选择 `src/td_project/integration.al`。
2. 确认左侧文件列表里有 56 个文件（其中 46 个参与综合），顶层是 `top`，器件是 EG4S20BG256。
3. 直接 Run，综合、布局布线、生成位流。
4. 用 USB-JTAG 下载 `integration.bit`，或者用 TD 重新生成的位流。
5. HDMI 接 HDMI-B，TF 卡插好，SW6 拨到数码管一侧，上电。

`integration.bit` 是工程目录里带的最新位流，和当前源码对应。如果要掉电保存，需要在 TD 里做一次外部 Flash 固化，具体步骤看板卡说明。

TD 只在打开工程时读 `integration.al`，退出时会按内存里的文件列表整份写回。所以不要在 TD 开着工程的时候从外部改 `.al`；要加文件，先在 TD 里 `Project → Add Files`，或者关掉 TD 改完再打开。

PLL 用了 3 个，IO 用了 35 个。开机画面的赛事视觉存在 `boot_logo_rom.v` 里，是 320×112 的 1bpp 点阵，显示时 2 倍放大到 640×224。

`src/user_source/hdl_source/test/` 下留了各模块的 testbench，覆盖缩放、转场、字幕、亮度对比度与 OSD、按键手势、音频波形、WAV 头解析和多曲目切换。开发阶段这些 testbench 在 ModelSim 下逐项比对过：缩放按像素检查，字幕按页检查黑条范围和字模位置，WAV 用假卡验证文件头、样点顺序和切歌不串台。具体用例可以直接看 `tb_*.v` 里的 `$display` 和断言。

上板现象：640×480 画面稳定，换图、缩放、翻转、转场、字幕翻页、亮度对比度调节、滤镜切换、切歌都正常；HDMI 电视能识别到 48 kHz 音频，声音和画面基本同步。

翻转档位和频谱窗口的示意图放在 `doc/` 下：`flip_demo.png` 是四种翻转效果，`audio_bars_preview.png` 是频谱柱的样子。

## 8. 已知限制

分辨率固定在 640×480，没有做 720p 或 1080p。这一版按 25 MHz 像素时钟、125 MHz TMDS 串行时钟设计，再高的分辨率需要重新评估 PLL 和时序。

缩放用的是最近邻，放大以后能看到像素块；0.5× 时图片只占屏幕中间一块，四周是黑边。这两个是当前算法的直接结果，不是显示故障。

转场是“先把当前画面压黑、中点换缓冲、再亮回来”的做法，不是两张图逐像素叠化。要做真正的 cross-dissolve，需要给帧读通路再加一路读通道。

字幕是固化在 `subtitle_rom.v` 里的点阵，运行时不能改字，也不能滚动。换文字要重新生成字模和文本 ROM。

亮度和对比度的步进比较大：亮度每次 16，对比度每次 64（Q8），按一下变化很明显。这是为了让按键次数少一点，想要细调可以改 `video_adjust.v` 里的步长。

WAV 只支持 48 kHz、16 位、单声道、连续存放；BMP 要放在卡的前 64 MB 并且连续。卡碎片多的时候，换图或播放可能失败。

数码管默认显示诊断信息，正式演示前可以改成功能显示。另外，板子没有板载喇叭，音频只能从 HDMI 输出。

```
NaiWa_HDMI_Player/
├─ README.md                  本说明
├─ integration.bit            最新位流
├─ demo/                      TF 卡演示素材（4 张 BMP + 1 首 WAV）
├─ doc/                       上电画面、翻转和频谱预览图
├─ src/
│  ├─ td_project/
│  │  ├─ integration.al       TD 工程文件
│  │  └─ al_ip/               PLL IP
│  └─ user_source/
│     ├─ constraints_source/  引脚、时序、EDID 约束
│     └─ hdl_source/
│        ├─ time/             视频处理、字幕、按键与开机画面
│        ├─ time2/            音频、HDMI 与顶层
│        ├─ SD/               TF 卡、SDRAM 与数码管
│        ├─ include/          SDRAM 底层定义
│        ├─ IP/               FIFO / PLL IP
│        └─ test/             testbench

```

`tools/` 里保留了工程自检脚本 `preflight_project.py`、BMP 转换脚本 `prep_images.py` 和旋律 ROM 生成脚本 `gen_melody_rom.py`。它们只在 PC 上使用，不会被 TD 综合。
